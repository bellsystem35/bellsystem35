# سياسة 404 وRedirects — BELL SYSTEM

## الهدف

الحفاظ على قيمة الروابط عند تغيير عناوين صفحات WordPress، وتقليل أخطاء 404 الحقيقية، ومنع سلاسل التحويل والتحويلات غير ذات الصلة. الموقع الرسمي لفرع BELL SYSTEM هو `bellsystem35.com`، والشركة الأم هي **Al Nahrayn Compony**.

## مبدأ أساسي

وجود 404 ليس سببًا كافيًا لإنشاء Redirect. القرار يعتمد على تاريخ URL ووجود روابط إليه ونيته وما إذا كان هناك بديل حقيقي.

## قواعد Redirect

1. استخدم `301` عندما نُقلت صفحة بصورة دائمة إلى URL بديل يطابق موضوعها ونيتها.
2. لا تحوّل جميع صفحات 404 إلى الصفحة الرئيسية.
3. إذا لم يوجد بديل مناسب، أبقِ `404` أو استخدم `410` عندما يكون الحذف متعمدًا ونهائيًا وفق التنفيذ التقني المناسب.
4. تجنب Redirect Chains مثل `A → B → C`؛ الأفضل `A → C` مباشرة.
5. تجنب Redirect Loops.
6. بعد تغيير URL، حدّث الروابط الداخلية وCanonical وSitemap وأي Schema يشير إلى العنوان القديم.
7. لا تغيّر Slug يعمل فقط لإضافة كلمة مفتاحية.
8. لا تحوّل صفحات مناطق مختلفة إلى صفحة لا تطابق نية الباحث لمجرد التخلص من تقرير 404.

## تصنيف أخطاء 404

### A — URL قديم له بديل مباشر

الإجراء: `301` إلى البديل الأقرب موضوعيًا، ثم تحديث الروابط الداخلية.

### B — URL به خطأ كتابي أو رمز زائد

الإجراء: أصلح مصدر الرابط أولًا. إذا كان URL الخاطئ معروفًا لمحركات البحث أو لديه روابط خارجية، يمكن إضافة `301` إلى النسخة الصحيحة.

### C — محتوى محذوف بلا بديل

الإجراء: `404`/`410` مناسب. لا Redirect عشوائي.

### D — URL مكرر أو نسخة Slug ثانية

الإجراء: حدد النسخة الأساسية، ثم استخدم Canonical أو `301` بحسب حالة الوصول الفعلية، وحدّث الربط الداخلي وSitemap.

### E — Soft 404

إذا كانت الصفحة تعيد `200` لكن محتواها يقول «غير موجود» أو شبه فارغ، أصلح status code أو المحتوى. لا تترك صفحة فارغة بـ`200`.

## قبل تنفيذ أي Redirect

سجّل:

- URL المصدر.
- URL الوجهة.
- HTTP status الحالي للمصدر.
- سبب التحويل.
- هل توجد روابط داخلية للمصدر؟
- هل الوجهة تطابق النية؟
- تاريخ التنفيذ.

## بعد التنفيذ

1. اختبر المصدر وتأكد من `301` واحد مباشر.
2. اختبر الوجهة وتأكد من `200` وقابليتها للفهرسة إذا كانت مقصودة لذلك.
3. حدّث جميع الروابط الداخلية القديمة.
4. تأكد أن Sitemap لا تحتوي URL القديم.
5. راجع Canonical للوجهة.
6. راقب Search Console ولا تبدأ Validation جديدًا قبل التأكد من إصلاح العينات.
