# التدقيق التقني — BELL SYSTEM

> هذا الملف يحدد فحوصات يجب تنفيذها على الموقع المنشور. وجود الملف لا يعني أن كل الفحوصات قد نُفذت تلقائيًا.

## 1. الفهرسة

- التحقق من `robots.txt`.
- التحقق من XML Sitemap الفعلي في WordPress.
- فحص Canonical لكل صفحة مهمة.
- البحث عن `noindex` غير المقصود.
- فحص حالات HTTP: 200 و301 و404 و5xx.
- استخدام Google Search Console لفحص عناوين URL المهمة.

## 2. بنية الصفحة

- H1 واحد وواضح.
- Title فريد لكل صفحة.
- Meta Description مفيدة وغير مكررة.
- Breadcrumb عند الحاجة.
- روابط داخلية منطقية.
- عدم وجود صفحات يتيمة.

## 3. الأداء

- ضغط الصور وتحويل الصور المناسبة إلى WebP.
- أبعاد الصور محددة لتقليل Layout Shift.
- تقليل JavaScript وCSS غير الضروري.
- مراجعة Largest Contentful Paint وInteraction to Next Paint وCumulative Layout Shift.
- اختبار الهاتف قبل سطح المكتب لأن جزءًا كبيرًا من البحث المحلي يتم عبر الهاتف.

## 4. Schema

- مطابقة البيانات المنظمة للمحتوى الظاهر.
- عدم تكرار LocalBusiness أو Service من أكثر من مصدر دون حاجة.
- عدم إضافة مراجعات أو أسعار أو عروض غير حقيقية.
- اختبار Structured Data بعد النشر.

## 5. التحويلات

الأحداث الأساسية:

- نقرة اتصال.
- نقرة WhatsApp.
- إرسال نموذج.

يجب التمييز بين النقر وبين إتمام الإجراء؛ نقرة WhatsApp لا تثبت أن الرسالة أُرسلت أو أن العميل أصبح Lead.

## 6. الروابط

- فحص الروابط الداخلية المكسورة.
- تجنب سلاسل Redirect غير الضرورية.
- استخدام روابط HTTPS.
- عدم وضع روابط تجريبية أو Placeholder في الصفحات المنشورة.

## 7. الأمان

- لا مفاتيح API أو كلمات مرور أو Tokens داخل المستودع.
- لا بيانات عملاء داخل ملفات التوثيق.
- استخدام Secrets في خدمات CI/CD عند الحاجة.

## 8. النتيجة

يُسجل لكل فحص: التاريخ، النطاق، الحالة، المشكلة، الإجراء، وحالة إعادة الاختبار. لا تُعتبر المشكلة مغلقة بمجرد تعديل الكود؛ يجب إعادة الاختبار.
