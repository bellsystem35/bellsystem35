# خطة الفهرسة والاسترداد — Al Nahrayn Compony / BELL SYSTEM

## النطاق

هذه الخطة تخص صفحات الموقع الرسمي لفرع **BELL SYSTEM** على `bellsystem35.com`. الشركة الأم هي **Al Nahrayn Compony**، لكن تغيير هوية الكيان لا يُستخدم كوسيلة لفرض الفهرسة؛ الأولوية لجودة الصفحة وسلامتها التقنية واتساقها مع الموقع.

## قبل طلب الفهرسة

لكل URL مرشح للفهرسة، تحقق بالترتيب من:

1. الصفحة منشورة وتعيد HTTP `200`.
2. لا يوجد `noindex` غير مقصود في HTML أو HTTP headers.
3. Canonical ذاتي أو يشير عمدًا إلى النسخة الأساسية الصحيحة.
4. الصفحة موجودة في Sitemap الرسمية إذا كانت قابلة للفهرسة.
5. توجد روابط داخلية حقيقية إليها من صفحات مفيدة، وليست صفحة يتيمة.
6. المحتوى مختلف ومفيد بما يكفي ولا يعتمد على استبدال اسم المنطقة داخل قالب مكرر.
7. العنوان وH1 والوصف والمحتوى متوافقون مع نية الصفحة.
8. الصفحة تعمل على الهاتف ولا توجد مشكلة رندر أساسية.
9. لا توجد نسخة URL أخرى تنافسها بسبب HTTP/HTTPS أو www/non-www أو slash أو slug بديل.

## حالة «تم الزحف إلى الصفحة - لم تتم فهرستها حاليًا»

لا نكرر طلب الفهرسة فقط. يتم أولًا تشخيص السبب المحتمل:

- محتوى ضعيف أو قريب جدًا من صفحات أخرى.
- صفحة منطقة بلا قيمة محلية كافية.
- Canonical أو إشارات داخلية غير واضحة.
- صفحة يتيمة أو منخفضة الأهمية داخل بنية الموقع.
- عدد كبير من الصفحات المتشابهة المنشورة دفعة واحدة.
- مشاكل جودة أو رندر أو استجابة خادم.

### مسار المعالجة

1. قارن الصفحة بالصفحات المنافسة داخل الموقع نفسه.
2. دمج أو تحسين الصفحات المتشابهة بدل إبقاء نسخ ضعيفة.
3. أضف قيمة أصلية: المشكلة، طريقة الخدمة، نوع الموقع، الأسئلة الفعلية، وروابط ذات صلة.
4. حسّن الربط الداخلي من صفحة الخدمة الأساسية وصفحة المنطقة/الدليل المناسبة.
5. تحقق من Canonical وSitemap.
6. أعد الفحص في URL Inspection ثم اطلب الفهرسة مرة واحدة بعد الإصلاح الجوهري.
7. راقب النتيجة بدل إجراء تعديلات يومية صغيرة بلا هدف.

## معالجة 404

صنّف كل 404 إلى واحدة من ثلاث حالات:

- **لها بديل مباشر:** استخدم `301` إلى أقرب صفحة تطابق النية.
- **خطأ في رابط داخلي:** أصلح الرابط في المصدر، وأضف Redirect فقط إذا كان URL القديم قد استُخدم أو فُهرس سابقًا.
- **صفحة محذوفة بلا بديل:** اترك `404` أو `410` مناسبًا بدل تحويلها عشوائيًا للرئيسية.

لا يتم تحويل جميع أخطاء 404 إلى الصفحة الرئيسية.

## Search Console

بعد الإصلاح:

1. استخدم URL Inspection.
2. تحقق من إمكانية الزحف والفهرسة.
3. قارن User-declared canonical مع Google-selected canonical.
4. اطلب الفهرسة للصفحات المهمة فقط بعد الإصلاح.
5. راقب تقارير Page indexing وSitemaps والأداء.
6. عند فشل Validation، راجع عينات URLs الفاشلة قبل بدء تحقق جديد.

## Sitemap

Sitemap الخاصة بـWordPress/إضافة SEO هي المصدر الأساسي للموقع. لا تُنشأ Sitemap منافسة من GitHub. يجب أن تحتوي Sitemap على URLs الأساسية القابلة للفهرسة فقط، وألا تحتوي عمدًا على Redirects أو 404 أو صفحات `noindex`.

## Robots.txt

يجب ألا يمنع Googlebot من الصفحات القابلة للفهرسة أو موارد CSS/JS الضرورية للرندر. لا يُستخدم robots.txt كبديل عن `noindex` لإزالة صفحة مفهرسة.

## ترتيب الأولويات

1. صفحات الخدمات الأساسية ذات النية التجارية الواضحة.
2. صفحات المناطق التي لديها محتوى محلي أصلي وقيمة حقيقية.
3. صفحات الثقة والتواصل المهمة للمستخدم.
4. إصلاح الروابط الداخلية و404.
5. دمج/تقليل الصفحات المتكررة منخفضة القيمة.
6. طلب الفهرسة بعد الإصلاح، وليس قبله.

## قاعدة القياس

الفهرسة ليست هدفًا منفصلًا عن الجودة، وطلب الفهرسة لا يضمن الظهور أو الترتيب. يتم تقييم النجاح من خلال الفهرسة الصحيحة، مرات الظهور، الاستعلامات، النقرات والتحويلات، مع الحفاظ على هوية متسقة: **Al Nahrayn Compony → BELL SYSTEM → bellsystem35.com**.
