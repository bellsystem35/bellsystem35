# استراتيجية SEO المحلي — Al Nahrayn Compony / BELL SYSTEM

## هوية المشروع

**Al Nahrayn Compony (النهرين)** هي الشركة الأم، و**BELL SYSTEM** فرع تابع لها. هذه العلاقة يجب أن تظهر بصورة طبيعية ومتسقة في المصادر الرسمية، دون تغيير أسماء الملفات التجارية أو الحسابات لمجرد إضافة كلمات مفتاحية.

## الهدف

تنظيم صفحات BELL SYSTEM للخدمات التي يقدمها فعليًا بحيث تخدم نية الباحث محليًا وتدعم الثقة في الكيان، مع تجنب الصفحات المتكررة أو الضعيفة أو المصممة فقط لاستهداف محرك البحث.

## قواعد كل صفحة

1. عنوان فريد يصف الخدمة والمنطقة عند وجود سبب حقيقي لصفحة محلية مستقلة.
2. Meta Description فريد ومطابق للمحتوى.
3. H1 واحد واضح.
4. محتوى أصلي يشرح المشكلة والحل والخدمة في السياق المحلي.
5. روابط داخلية إلى صفحة الخدمة الأساسية وصفحات المنطقة والصفحات ذات الصلة عندما تفيد المستخدم.
6. صور مناسبة ومحسنة مع Alt وصفي غير محشو بالكلمات.
7. Canonical يشير إلى النسخة الأساسية المنشورة.
8. عدم إنشاء صفحة منطقة إذا لم يكن لها محتوى مفيد ومختلف.
9. عدم تكرار اسم الشركة الأم والفرع في كل عنوان أو فقرة بصورة مصطنعة.
10. بيانات الاتصال والهوية يجب أن تطابق المصدر الرسمي.

## صفحات المناطق وDoorway Pages

لا يكفي تغيير اسم المنطقة داخل نص ثابت. يجب أن تضيف الصفحة قيمة محلية حقيقية وأن تكون قابلة للفهم بمفردها. إذا كانت عدة صفحات متشابهة جدًا، فالأولوية لتحسين البنية والمحتوى والربط الداخلي أو الدمج المناسب بدل إنتاج نسخ إضافية.

## NAP والكيان التجاري

استخدم اسم العلامة وبيانات الاتصال والمعلومات التجارية كما هي في المصدر الرسمي. لا تضف عنوانًا أو ساعات أو فروعًا أو أرقامًا غير مؤكدة. إذا كان النشاط Service Area Business، فلا ننشر عنوانًا غير مخصص لاستقبال العملاء لمجرد تحسين الظهور المحلي.

## الشركة الأم والفرع

- لا يتم تغيير اسم BELL SYSTEM إلى اسم مركب محشو بالكلمات.
- لا يتم إنشاء صفحة Google Business Profile إضافية للنهرين أو للفرع إلا إذا كان الكيان مؤهلًا فعليًا وفق قواعد المنصة.
- يفضّل وجود توضيح طبيعي على الموقع بأن BELL SYSTEM فرع تابع لـ Al Nahrayn Compony عندما يكون ذلك مطابقًا للواقع التجاري.
- الحسابات الاجتماعية تُربط بالكيان الذي تمثله فعليًا.

## إشارات الثقة الرقمية

تُراجع دوريًا اتساقات الموقع الرسمي، Google Business Profile، 2GIS، GitHub والحسابات الاجتماعية المؤكدة. الهدف هو صحة الهوية وليس تكرار نفس الكلمات في عشرات المواقع.

## القياس

تُستخدم بيانات Search Console لقياس الاستعلامات والصفحات والنقرات ومرات الظهور وحالات الفهرسة، ثم تُحسن الصفحات بناءً على البيانات. لا نعتبر GitHub أو كثرة الروابط بديلًا عن جودة صفحات WordPress أو تجربة المستخدم أو صحة الملف التجاري.

6. اتساق المنصات والحسابات الرسمية.
7. القياس والتحسين المستمر دون حشو أو تضليل.
