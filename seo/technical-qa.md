# 🔎 Technical QA — BELL SYSTEM

## الغرض

هذا الملف هو سجل فحص تقني للمشروع. يميّز بين ما تم التحقق منه داخل مستودع GitHub وما يحتاج إلى تحقق مباشر داخل WordPress والموقع والإضافات وخدمات Google.

## 1. Repository QA

- [x] المستودع يعمل على الفرع `main`.
- [x] بنية `services/` و`areas/` و`seo/` و`documentation/` موجودة.
- [x] تم إضافة `.gitignore` لمنع ملفات الأسرار والملفات المحلية الحساسة.
- [x] تم إضافة `SECURITY.md`.
- [x] لا تُضاف مفاتيح Google Ads الحقيقية إلى المستودع.
- [x] لا تُحفظ كلمات المرور أو API Keys أو Tokens في التوثيق.

## 2. SEO On-Page — يحتاج تحققًا من WordPress

- [ ] عنوان `<title>` فريد لكل صفحة منشورة.
- [ ] Meta Description فريدة ومناسبة للنية البحثية.
- [ ] H1 واحد فقط في الصفحة.
- [ ] Canonical يطابق URL الصفحة المنشورة.
- [ ] عدم وجود `noindex` غير مقصود.
- [ ] العناوين H2/H3 مرتبة منطقيًا.
- [ ] المحتوى المحلي أصلي وليس نسخة مع تبديل اسم المنطقة فقط.

## 3. Technical SEO — يحتاج تحققًا حيًا

- [ ] `robots.txt` لا يمنع صفحات مهمة.
- [ ] XML Sitemap صادر من المصدر الأساسي للموقع.
- [ ] صفحات 404 والروابط الميتة تحت السيطرة.
- [ ] Redirects القديمة لا تسبب حلقات أو سلاسل غير ضرورية.
- [ ] HTTPS يعمل على جميع الصفحات.
- [ ] Canonical وSitemap متوافقان.
- [ ] الصفحات المهمة قابلة للاكتشاف عبر روابط داخلية.

## 4. Performance / Core Web Vitals

- [ ] LCP ضمن المستوى المستهدف.
- [ ] INP ضمن المستوى المستهدف.
- [ ] CLS ضمن المستوى المستهدف.
- [ ] الصور بصيغ حديثة مثل WebP عند ملاءمتها.
- [ ] الصور مضبوطة الأبعاد لتقليل Layout Shift.
- [ ] الصور خارج الشاشة تستخدم Lazy Loading عند ملاءمتها.
- [ ] JavaScript وCSS غير الضروريين مخففان.
- [ ] الخطوط لا تسبب تأخيرًا أو تبديلًا مزعجًا.

## 5. Mobile / UX

- [ ] التصميم RTL صحيح على الهاتف.
- [ ] أزرار الاتصال وWhatsApp سهلة الوصول.
- [ ] النص قابل للقراءة دون تكبير.
- [ ] لا يوجد Horizontal Overflow.
- [ ] CTA الرئيسي واضح.
- [ ] نموذج التواصل يعمل على الهاتف.
- [ ] صفحات المناطق لا تعتمد على نص مكرر طويل.

## 6. Images

- [ ] Hero image حقيقية وليست Placeholder.
- [ ] أسماء الملفات وصفية.
- [ ] ALT يصف الصورة دون حشو كلمات مفتاحية.
- [ ] WebP يستخدم حيث يكون مناسبًا.
- [ ] لا توجد صور كبيرة بلا داعٍ.

## 7. Structured Data

- [ ] Schema يطابق المحتوى الظاهر.
- [ ] عدم تكرار LocalBusiness بين الكود اليدوي وإضافة SEO.
- [ ] Service يستخدم فقط في صفحات الخدمات المناسبة.
- [ ] BreadcrumbList يطابق مسار الصفحة.
- [ ] FAQPage لا يستخدم إلا عندما تكون الأسئلة والأجوبة ظاهرة للمستخدم.
- [ ] عدم استخدام Offer أو Review أو AggregateRating دون بيانات حقيقية قابلة للتحقق.

## 8. Conversion Tracking

الأحداث المخططة:

- `phone_click`
- `whatsapp_click`
- `lead_form_submit`

قواعد القياس:

- نقرة WhatsApp ليست بالضرورة Lead مكتملًا.
- إرسال النموذج يجب أن يُقاس عند نجاح الإرسال الفعلي، وليس عند مجرد الضغط على الزر.
- يجب اختبار Google Ads Conversion ID وLabels الفعلية داخل بيئة الإنتاج قبل تفعيل القياس النهائي.
- لا تضع معرفات أو مفاتيح حقيقية داخل GitHub.

## 9. Google Search Console

- [ ] الملكية مؤكدة.
- [ ] Sitemap الصحيح مُرسل.
- [ ] فحص URL للصفحات الأساسية.
- [ ] مراجعة Page Indexing.
- [ ] مراجعة Duplicate without user-selected canonical.
- [ ] مراجعة Crawled - currently not indexed.
- [ ] مراجعة Performance حسب Query وPage وCountry.

## 10. Google Ads

الحملة المقترحة للشارقة مقسمة حسب النية:

1. تسليك مجاري.
2. شفط مجاري وبيارات.
3. تنظيف البالوعات وغرف التفتيش.
4. معالجة روائح الصرف.

قواعد التشغيل:

- ابدأ بـ Phrase وExact عندما تكون النية التجارية واضحة.
- راجع Search Terms دوريًا.
- أضف Negative Keywords بناءً على البيانات الفعلية.
- لا تعتبر النقرة تحويلًا.
- اربط التحسين بالـ Leads الفعلية قدر الإمكان.

## 11. Internal Linking

الهيكل المستهدف:

`الرئيسية → الخدمة → دليل الخدمة → المنطقة → الخدمة المرتبطة`

كل صفحة منطقة يجب أن تمتلك سببًا حقيقيًا لوجودها، ومحتوى محليًا مفيدًا، وروابط مرتبطة بالخدمة، وألا تكون مجرد نسخة من صفحة منطقة أخرى.

## 12. Security

- [x] `.gitignore` أُضيف.
- [x] `SECURITY.md` أُضيف.
- [ ] مراجعة Git history إذا حدث تسريب سابق.
- [ ] تفعيل حماية الفرع وقواعد المراجعة إذا كانت مناسبة للمستودع.
- [ ] مراجعة صلاحيات التطبيقات المتصلة بـ GitHub خارج المستودع.

## 13. Release Gate

لا تعتبر عملية الإطلاق النهائية مكتملة حتى يتم التحقق من:

1. الصفحة الرئيسية.
2. صفحات الخدمات الأساسية.
3. صفحات المناطق.
4. Canonical وSitemap.
5. Mobile UX.
6. Forms.
7. Phone/WhatsApp tracking.
8. Schema.
9. Search Console.
10. Google Ads conversions.

## الحالة الحالية

**Repository QA:** تم تنفيذ طبقة أساسية من الفحص والتنظيم داخل GitHub.

**Website QA:** يحتاج تحققًا مباشرًا من WordPress والموقع المنشور قبل إعلان نجاح نهائي في الفهرسة أو الأداء أو التحويلات.

**القاعدة:** لا نخلط بين وجود وثيقة داخل GitHub وبين نجاح الإعداد في الموقع الفعلي.
